## 1. Tenancy and row-level security [K]

- All 52 tables with `organization_id` have `ENABLE ROW LEVEL SECURITY`. Every app policy keys on
  `nullif(current_setting('app.organization_id', true), '')::uuid` and has a `WITH CHECK` on the tenant
  (migrations 0002, 0005 and 0009 to 0035). No `USING (true)` policy exists for `tempo_app`.
- RLS is **enabled, not forced**, on purpose (`docs/26`; `0002:9-12`). The migrator owns every table and the
  `SECURITY DEFINER` lookups rely on that. Accepted, recorded as **SR-14**: the migrator's credentials must never
  reach a runtime Lambda, and today they don't (the API and worker roles read only the app and platform passwords).
- `BootstrapRoles.cs` creates `tempo_app` and `tempo_platform` without `BYPASSRLS`; they own nothing.
- The four `SECURITY DEFINER` functions pin `search_path = pg_catalog, pg_temp`, revoke `EXECUTE` from `PUBLIC` and
  return only the row matching a 128-bit token hash, or refuse a studio that is not suspended (0002, 0008, 0020, 0023).
- `UnitOfWork` sets the RLS values with `set_config(..., true)` inside one transaction. `SetTenantAsync` has four
  callers, and each one moves only after a check (an invitation token plus a verified matching email, a join-code
  hash, or the caller's own rows).
- Gaps: **SR-10** (`identity.user_accounts` and `identity.external_identities` have no RLS, with full DML for the
  app role), **SR-15** (the memberships policy is `FOR ALL` across the caller's studios; `health_declarations` UPDATE
  on every column), and **SR-16** (`tempo_platform` reads all of `people.*`).

## 2. Authorization on every route [K]

- `TenantRouteFilter` takes the tenant from the route only. It answers 404 without an active membership, 403 for a
  suspended membership or studio, and 402 on writes in restricted mode. It fails closed when a route has no
  `RequirePermission`.
- Every tenant query read in the services also has an `organization_id = $1` predicate. The object-level checks hold:
  bookings (owner or `bookings.manage`), roster and attendance (staff or the class's instructor), notes, media by
  purpose, merge survivors from the candidate pair, and a forced transfer's target in the same studio.
- Step-up had three gaps against `docs/27`. They are fixed in #556:
  - **SR-1:** `PATCH /members/{id}` could grant admin without a recent sign-in, unlike `PUT /members/{id}/roles`.
  - **SR-2:** the operator's forced owner transfer had no step-up.
  - **SR-3:** cancelling an ownership transfer had none either.
- Also: **SR-18** (no fallback authorization policy) and **SR-19** (a disabled account can call `DELETE /me`, which
  needs a decision).
- **SR-19, today's behaviour (for Kris to decide; nothing changed):** `DELETE /me` reads the token's sign-in
  (`SignInOf`), not `CallerAccount`, so the `account.disabled` refusal does not apply and `AccountDeletionService`
  doesn't look at the account's status. A disabled account with a valid token, a sign-in in the last 10 minutes and its
  email typed can delete itself; a live owner still gets 409 `account.sole_owner`. The choice: keep it, so a person
  blocked from the product can still erase their data, or answer 403 and handle erasure by request.

## 3. Tokens and sessions [K]

- Both schemes check the issuer, the JWKS signature, the lifetime (1 minute skew), `token_use = access` and the
  `client_id` allow-list (`CognitoAuthentication.cs:74-118`). A token from the wrong pool fails the issuer check with
  401. The default policy is customer-only, and the platform policy is operator-only.
- Step-up reads `auth_time` (10 minutes, and a missing claim fails). Cognito keeps `auth_time` across a refresh.
- Just-in-time provisioning takes the email and its verification from Cognito `AdminGetUser`, never from token
  claims. A disabled account is refused at session start and on every request (`CallerAccount`).
- Hardening: **SR-17** (no `ValidAlgorithms`), fixed in #571: RS256 only, with signed tokens required. The member sign-in itself is **SR-11**: Essentials plan, no threat
  protection, MFA optional for members and staff, with owners' TOTP enforced by the API.

## 4. Health data [K]

- The key is 32 bytes per version in SSM, written with `Overwrite: false`, and fails closed with 503
  (`HealthDataKeys.cs`, `health-data-key.mjs`).
- AES-256-GCM uses a random 96-bit nonce per field and a 128-bit tag. The associated data is
  `org|declaration|column|keyVersion` (`HealthCipher.cs`), so a ciphertext can't be moved to another row, column or
  studio.
- Answers need `health.view` (the owner only), and every read is audited without content. Export decrypts only with
  `health.view`, audits each declaration and needs step-up. Erase deletes every declaration. Merge moves them to the
  survivor.
- No finding beyond SR-15's column grants and SR-16's platform reach.

## 5. The public surface: routes and limiters [K + O]

- Anonymous routes: the public studio GETs, `/health` and the OpenAPI document. Join, invitation preview and accept,
  and join-code preview all need a customer token.
- The public reads select no booking, roster or contact column. Availability is a bucket, not a head count. An
  instructor appears only with `public_profile`, and the inviter by first name only, with `show_name` on.
- Enumeration: an invitation preview answers the same for unknown, revoked, accepted and expired tokens. Join codes
  are 16 bytes, stored as hashes. Link codes carry 40 bits. Slugs are exact matches of at most 63 characters.
- Limiters: `AttemptLimiter` and `ClientRateLimiter` commit before the work and key on the gateway source or the
  CloudFront viewer address, never on a client header.
- Images: uploads are capped at 8 MB at S3 and again on read. There is a 12 MP pixel cap, a magic-byte check and a
  re-encode. The cover redirect goes only to a presigned S3 URL or a relative icon path.
- CORS: exact origins and `allowCredentials: false`, at the gateway and on the media bucket.
- Gaps:
  - **SR-5:** behind the edge, execute-api let callers skip the WAF. Fixed for production in #555.
  - **SR-8 and SR-9 (#560):** anonymous requests reach the Lambda through `{proxy+}`, and case variants of the public
    paths skip their throttles. Those throttles are one bucket for every caller.
  - **SR-13 (#564):** a repeat offer join grants another unpaid pass.
  - **SR-20:** `PublicRateLimitFilter` could be reset by anyone, and it keyed on the wrong address behind
    CloudFront. Fixed in #572.

## 6. Background work: worker, queue, webhooks, scheduler [K]

- `SendMessage` is granted only to the Scheduler role, the API role and the smoke role. Scheduler bodies are `{}`.
  Unknown message types fail and go to the DLQ after five tries, with an alarm. Partial batch responses are on.
- Push delivery claims rows with `FOR UPDATE SKIP LOCKED`. Endpoints must be on the https vendor allow-list, checked
  at subscribe and at send. The VAPID private key is readable by the worker only.
- The retention and tripwire jobs run as the platform role with time-bounded deletes and a count. The Neon usage
  function logs percentages only. There is no generic webhook intake yet (`docs/24` Phase 4).
- Hardening, fixed in #571: **SR-21** (the outbox handler logged a body prefix), **SR-22** (push followed
  redirects).

## 7. Infrastructure, secrets and IAM [K]

- **Least privilege per Lambda:**
  - The API reads exactly its SSM parameters. It may write and read S3 only under `incoming/*` and `media/*`, send
    only to the work queue, and call `AdminGetUser`/`AdminDeleteUser` only on the customer pool.
  - The worker, the migrator, the Neon usage function and the dev canary each have only their own parameters.
  - No `iam:PassRole` anywhere.
- **Secrets** are SecureStrings under `/tempo/<env>/...`, written by a person and never in templates.
- **The media bucket** blocks public access and has SSE-S3, `enforceSSL` and `BucketOwnerEnforced`. A presigned POST
  carries an exact key per tenant, a size range of 1 B to 8 MB and an exact content type. `incoming/` expires after a
  day.
- **Queues and topics** enforce SSL; the queues are encrypted and have a DLQ.
- **Log groups** are explicit: 14 days in dev, 90 in prod, and infinite retention is refused.
- **Cognito:** passwords of at least 12 characters (customers) and 14 (operators), `preventUserExistenceErrors`, no
  client secrets, code grant only. Operator tokens last 15 minutes, with MFA required outside dev.
- **cdk-nag** gates CI over dev, dev with the edge, and prod (#555 adds dev as deployed). Every suppression has a
  reason. The weak ones are SR-25 and SR-29.
- **The GitHub OIDC role** trusts only `main` of this repository by its immutable ids, with `aud` pinned. Its
  administrator reach is #123, Kris's decision, recorded here and not reopened.
- Findings: **SR-5** (#122, #555), **SR-23** to **SR-29** (#566).

## 8. CI and the supply chain [K]

- Only `pull_request`, `push` and `workflow_dispatch` triggers: no `pull_request_target` and no `workflow_run`. Fork
  PRs get no secrets and no OIDC. No `${{ github.event.* }}` is interpolated into a `run:`. Every action is pinned to
  a full SHA.
- pnpm 11.5 with `minimumReleaseAge: 1440`, `blockExoticSubdeps`, `trustPolicy: no-downgrade` (two justified
  exceptions), builds denied, and `--frozen-lockfile` everywhere. `pnpm audit --audit-level high` runs with an empty
  ignore list.
- Dependabot covers npm, NuGet and Actions, monthly, with a 7-day cooldown. CODEOWNERS is set.
- Audits on 2026-11-01:
  - `dotnet list Tempo.sln package --vulnerable --include-transitive`: no vulnerable package in any of the seven
    projects.
  - `pnpm audit`: one moderate advisory, minimatch below 11.0.1 (a denial of service through glob patterns). All
    three copies are development tools only (eslint, typescript-eslint, and `@redocly/openapi-core` under
    `openapi-typescript`), and nothing ships in the app bundles. It is left to Dependabot.
- Findings:
  - **SR-6 (high, #558):** `id-token: write` is set for the whole deploy workflow, so every install and build step can
    reach the deploy role.
  - **SR-7 (#559):** the Cloudflare token is visible to installs and builds, and wrangler runs outside the lockfile.
  - **SR-12 (#563):** NuGet locked mode is not enforced.
  - **SR-30 to SR-32 (#567):** unpinned tools, raw migrator output in public logs, and no scheduled full secret scan.
  - SR-6, SR-7 and #567 are workflow changes, so they wait for Kris's approval on #553.

## 9. Logs, errors and personal data [K]

- Unhandled exceptions return a generic 500 with a correlation id. Domain problems carry fixed messages, without
  values. `IncludeErrorDetail` and `ShowPII` are off. Correlation ids must match `^[A-Za-z0-9-]{1,64}$`.
- The audit log keeps ids, roles, field names and reasons, with no emails, names or health answers. The API Gateway
  access log has the route key, without the path or query. Invitation tokens and join codes travel in bodies and URL
  fragments only.
- **SR-4 (medium, #557):** ASP.NET's hosting lines logged the query string at Information. Logs Insights on dev over
  14 days counted 118 `/people` and 25 `/search` requests logged with a search term in the query (counts only). A
  search term is a name, a phone or an email. Fixed in #557: hosting diagnostics are set to Warning, and Serilog's
  request line (path, status and time) stays.

## 10. The apps [O]

Read against `main` at `7c0d0ad`, as code only. Nothing was run against dev.

- **Headers:**
  - One `_headers` file is generated by `pages-headers.ts:14-20` and written into both apps (`deploy-development.yml:221`).
  - The CSP is strict: `script-src 'self'` with no `unsafe-eval`. `unsafe-inline` is in `style-src` only (`edge-stack.ts:47`).
  - Also set: `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`, and `form-action 'self'` plus Cognito.
  - `connect-src` allows only the site itself, the API, Cognito and the media bucket. `img-src` has no `https:` wildcard.
  - HSTS, nosniff, `X-Frame-Options` and `Referrer-Policy` are set too.
  - Gaps: no `Permissions-Policy` (**SR-35**); the CSP is always built from the development config (**SR-37**).
- **`_worker.js` (client-web):**
  - `_routes.json` sends only `/s/*` to the worker.
  - Anything other than a GET from a known link-preview crawler on a strictly matched `/s/<slug>[/prices|/c/<uuid>|/o/<uuid>]` path goes straight to `env.ASSETS.fetch`, so it keeps `_headers` (`_worker.js:21-39,172-176`).
  - `src` must match `[A-Za-z0-9_-]{1,40}`, and the API path is built with `encodeURIComponent`, so no request input can reach another API route.
  - Every studio, class, offer and inviter string goes through `escapeHtml` into a double-quoted meta value.
  - `og:image` is always the API's own cover route.
  - The preview page carries `default-src 'none'`. It lacks HSTS and `Referrer-Policy`, because `_headers` doesn't apply to worker responses (**SR-36**).
- **Sign-in and redirects:**
  - PKCE uses S256. `state` and `verifier` come from `randomUrlSafe`, sit in `sessionStorage` for one round trip, and are removed on read (`authClient.ts:136-137,282-286`). `state` is checked before the code is used (`:170`).
  - No id token is kept, so there is no nonce.
  - `returnTo` passes through `safeReturnTo` (`authClient.ts:320-327`). It rejects `//`, `/\`, `/auth/` and control characters, so `javascript:` and protocol-relative targets fall back to `/` (test at `authClient.test.ts:373`).
  - Both login pages apply it to the query parameter. The callback reads `returnTo` from `sessionStorage`, never from the URL. There is no `next` parameter.
  - The only `window.location` writes are the Cognito URL and same-origin paths.
- **Storage and the service worker:**
  - The session is in `localStorage` (`tempo.<app>.session`). The strict `script-src` limits the XSS exposure, and the refresh token is revoked on sign-out (`authClient.ts:257`).
  - Pending invite and join secrets are in per-tab `sessionStorage`.
  - `sw.js` handles push only: it has no fetch handler and no cache, so no API answer is ever cached. A notification click opens a same-origin URL.
  - Gaps: two of the three sign-out buttons leave the device's push subscription on the server (**SR-33**), and per-person keys survive sign-out (**SR-34**).
- **White-label and user content:**
  - There is no `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML` in `apps/*/src` or `packages/*/src`.
  - The studio accent is a fixed id set as `data-accent` and matched by CSS selectors (`accent.ts:35`). No studio-supplied string reaches a CSS variable, `style=` or `url()`.
  - Names, bios and descriptions render as React text.
  - Links in markdown and templates must be `https://` or a single-slash path (`richText.tsx:31-34`, `TemplatePreview.tsx:38-42`).
  - Instagram handles and playlist URLs are validated by the API against a host allow-list (`Instructors.cs:236-268`) before the app builds a fixed-host link.
- **The `no-raw-html` test** (`apps/client-web/src/app/no-raw-html.test.ts`):
  - It covers `apps/*/src` for `dangerouslySetInnerHTML`, `.innerHTML =` and `insertAdjacentHTML`, with an empty allow-list.
  - It misses `packages/*/src`, `public/*.js`, `outerHTML`, `document.write` and `innerHTML +=` (**SR-38**). A hand grep of those places finds no uses today.
- **`pnpm audit`:**
  - Both apps' production graphs have no known vulnerabilities.
  - The workspace has one moderate advisory, minimatch < 11.0.1 (GHSA-g3hv-75wg-m249), reached only through eslint and other dev tooling. It never ships to a browser.
